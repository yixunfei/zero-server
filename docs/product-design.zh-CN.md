# zeroServer 产品设计文档

## 1. 产品概述

zeroServer 是一个 MIT 开源的通用企业级 Java 游戏服务器框架，面向多项目复用、组件化最小原型开发、极致核心性能、高效业务开发和长期稳定运营。

zeroServer 的核心形态是：

```text
游戏专用运行时内核 + Starter/Adapter 生态
```

核心内核负责稳定、高性能、低依赖的运行时能力；Starter 提供开箱即用的项目体验；Adapter 负责对接 MongoDB、Redis、Kafka、PostgreSQL、Nacos、Prometheus、Grafana 等具体基础设施。

## 2. 产品愿景

zeroServer 希望让 Java 游戏服务器开发从“重复搭底座”转向“专注业务与世界构建”。

框架应让个人开发者可以快速启动一个 RPG 场景同步原型，也让大型团队可以在同一套规范下扩展到 Actor 集群、跨服调用、微服务拆分、运营后台、热更、日志数据链路和多项目复用。

## 3. 设计理念

### 3.1 核心性能做到极致兜底

线程模型、通信协议、编解码方式、远程调用、数据库访问、定时任务、缓存、Actor 调度和事件派发，是游戏服务器的基础承重结构。

这些部分必须追求：

- 低延迟。
- 低分配。
- 高吞吐。
- 可背压。
- 可降级。
- 可观测。
- 可基准测试。
- 可压测复现。

性能主张必须由测试、压测、基准、火焰图或明确推导支撑。

### 3.2 业务开发面向事件与协议

业务程序员不应反复编写网络解析、协议路由、线程切换、错误码封装、日志埋点和测试样板。

zeroServer 通过协议 DSL 生成：

- 协议 DTO。
- 事件接口，`.si` 主入口当前按协议方法生成 `XXXEventBO`。
- 默认实现模板，`.si` 主入口当前按协议方法生成 `XXXEventBOImp`。
- Java 测试模板。
- ErrorCode 模板。
- 协议文档。
- C#、TypeScript、GDScript 客户端协议代码。

业务程序员主要实现生成的事件接口，即可完成绝大部分业务功能。

### 3.3 业务强约束，组件灵活插件化

zeroServer 在业务范式上保持强约束：

- 事件驱动。
- 服务模块化。
- 线程绑定状态修改。
- 跨 Actor 消息调用。
- 统一数据访问。
- 统一日志与错误码。

zeroServer 在基础设施上保持插件化：

- 协议可插拔。
- 编解码可插拔。
- RPC 可插拔。
- 数据库可插拔。
- 缓存可插拔。
- 服务发现可插拔。
- 监控与日志落地可插拔。

### 3.4 从最小原型到企业级分布式

框架必须支持两种使用方式：

- 单进程全模块运行：适合个人、本地开发、原型验证和自动化测试。
- 分布式多进程运行：适合正式上线、多项目复用、跨服、扩容和微服务拆分。

业务 API 应尽量保持一致，避免项目从原型走向生产时大规模重写。

## 4. 目标用户

### 4.1 个人开发者

希望快速搭建一个可运行的 RPG 场景同步服务器，并能在此基础上扩展登录、场景、移动、AI NPC、GM 查询、日志和监控。

### 4.2 游戏后端团队

需要标准化多人协作方式，避免每个项目重复设计网络、协议、数据、日志、监控和后台接口。

### 4.3 多项目平台团队

需要一套可复用服务器框架，支撑多个游戏项目共享通用基础设施，同时允许项目按业务差异替换组件。

### 4.4 AI 辅助开发场景

希望自动化工具和大模型能够长期参与代码生成、代码评审、性能分析、测试生成、文档维护和发布说明生成，并遵循公开的贡献指南、模块边界、质量门禁与维护者评审流程。

## 5. 适用游戏类型

zeroServer 是通用框架，不绑定单一游戏类型。

优先支持：

- RPG 场景同步。
- 开放世界服务端。
- 状态同步。
- 帧同步。
- 房间。
- 场景。
- 玩家实体。
- 动态实体。
- AI NPC。
- 动态世界运转逻辑。

卡牌、回合制、SLG、休闲长连接、跨服战场等类型可以基于相同事件、数据、通信和运营能力扩展。

## 6. 核心能力

### 6.1 网络通信

基础网络使用 Netty。

服务端至少支持：

- TCP。
- KCP。
- WebSocket。

后台与远程调用至少支持：

- HTTP REST。
- Kafka RPC。

### 6.2 协议与编解码

框架需要支持：

- Protobuf。
- JSON。
- 自研二进制协议。
- Cap'n Proto Adapter。

实际业务使用哪一种由项目决定。框架通过 SPI 提供统一协议注册、编码、解码、错误处理和代码生成入口。

### 6.3 事件系统

事件类型包括：

- 客户端协议事件。
- 服务内部事件。
- 内部跨服与转发事件。
- 业务跨服事件。
- 运营后台事件。
- 定时事件。
- 数据变更事件。
- 异常与日志变更事件。
- dev 指令事件。

事件总线应支持：

- 优先级。
- 拦截器。
- 重试。
- 死信。
- 幂等。
- 顺序保证。

### 6.4 线程与 Actor

默认线程模型：

- Netty IO 线程。
- 逻辑 Actor 线程。
- 可异步远程 IO 线程。
- 定时任务线程。
- Java 21 虚拟线程，用于低频后台、GM、远程 IO。

玩家在线数据默认绑定 player actor，场景状态默认绑定 scene actor，跨 Actor 调用必须走消息。

### 6.5 RPC

RPC 偏向服务接口调用，支持：

- request/response。
- oneway。
- broadcast。

同步 RPC 可通过 Kafka 实现，默认超时 3 秒，可配置。同步 RPC 需要 `correlationId`、`replyTopic`、`serviceName`、`methodName`、`traceId`、`timeoutAt`。

框架应优先鼓励异步回调通知。

### 6.6 数据与缓存

默认职责：

- PostgreSQL：平台、账号、后台、渠道、服务器基础信息。
- MongoDB：游戏业务主数据。
- Redis：缓存、排行榜、短期状态、追加式持久化过渡方案。

框架提供统一 `Repository` / `DataService` 抽象，并支持本地缓存 + Redis 分布式缓存。

缓存能力：

- 自动加载。
- 写回。
- 失效。
- 版本号。
- 防击穿。
- 防穿透。

玩家在线数据常驻内存，定时异步落库，默认对象级脏数据追踪。

### 6.7 热更

热更等级：

```text
无感热更 -> 卡顿热更 -> 闪断热更 -> 降级熔断热更 -> 停机维护
```

支持范围：

- 配置热更。
- 活动热更。
- CGLIB 修复。
- ClassLoader 插件化活动。
- 集群热更同步。

核心代码不热更。

### 6.8 GM 与后台 API

zeroServer 不内置完整 Web 后台，但提供标准响应式 API 和接口实现。

能力包括：

- 公告。
- 服务器状态维护。
- 玩家查询。
- 封禁。
- 邮件。
- 道具发放。
- 充值订单失败补充。
- 在线人数。
- 日志检索。
- 配置发布。
- 热更发布。
- GM 指令。
- 运营活动开启。
- 兑换码/活动运营码生成。

权限模型：

- RBAC。
- IP 白名单。
- 审批流。
- dry-run。
- 审计日志。

### 6.9 日志与可观测性

日志分类：

- 运行日志。
- 业务日志。
- 玩家行为日志。
- 审计日志。
- 错误日志。
- 性能日志。
- 安全日志。

日志默认落地：

- 本地文件。
- Kafka。

监控能力：

- Prometheus。
- Grafana 默认 JSON 模板。
- 告警规则配置。

TraceId 从入口传递到 RPC、DB、MQ、日志、审计和指标。

## 7. MVP 范围

首个最小原型必须做到业务程序员开箱即用。

默认包含：

- 一键脚本或 Maven archetype 创建项目。
- 登录。
- 玩家加载。
- 场景进入。
- 移动事件。
- GM 查询。
- 标准日志。
- Prometheus 监控端点。
- 简单 Web 客户端 demo。
- 本地无 Docker 可运行。
- 可选 docker-compose 启动 MongoDB、Redis、Kafka、Nacos。

示例游戏方向：

```text
RPG 场景同步
```

## 8. 非目标

zeroServer 第一阶段不追求：

- 内置完整 Web 后台项目。
- 核心内核绑定具体中间件。
- 一次性实现所有游戏类型的高级玩法。
- 用没有证据的性能数字做宣传。
- 让业务直接面对线程池、Netty ByteBuf、Kafka 消费细节和数据库驱动细节。
- 对核心代码做无边界热更。

## 9. 产品边界

zeroServer 负责：

- 游戏服务器运行时。
- 事件驱动业务模型。
- 通信、协议、RPC、数据、缓存、日志、监控、GM API、热更的框架能力。
- 脚手架与示例。
- 代码生成工具。

zeroServer 不负责：

- 完整商业 Web 后台。
- 具体游戏业务内容。
- 美术资源、客户端 UI 和完整客户端工程。
- 下游数据中台实现。
- 具体机房和云平台运维。

## 10. 开源策略

zeroServer 使用 MIT License。

商业项目可以闭源使用 zeroServer。

当前不区分社区版、企业版和内部版。

示例项目未来建议使用独立 examples 仓库维护，框架主仓库只保留必要最小示例和脚手架。

## 11. 成功标准

zeroServer 第一阶段成功标准：

- 新用户可以一键启动 RPG 场景同步示例。
- 业务程序员可以通过生成的 `XXXEventBOImp` 完成登录、进场景、移动和 GM 查询。
- 单进程模式无需 Docker 可运行。
- docker-compose 可启动 MongoDB、Redis、Kafka、Nacos。
- 文档能解释核心模块职责和扩展方式。
- 日志、错误码、TraceId、Prometheus 指标在示例中真实可用。
- 自动化工具和 AI 辅助开发能够遵循 `CONTRIBUTING.md`、模块图与公开质量门禁安全参与后续开发。

第二阶段成功标准：

- 支持 Kafka RPC。
- 支持 Nacos 服务发现。
- 支持 MongoDB/Redis 数据落地切换。
- 支持 ClassLoader 活动插件。
- 支持 CGLIB 代理修复。
- 支持基础 GM 审批与 dry-run。
- 有 JMH 或压测基线。
