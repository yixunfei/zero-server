# 热更方案

## 1. 热更等级

zeroServer 热更按影响程度分级：

```text
无感热更
  -> 卡顿热更
  -> 闪断热更
  -> 降级熔断热更
  -> 停机维护
```

## 2. 热更优先级

优先级：

1. 配置热更：监听变化或接收通知后更新。
2. 活动热更：通过后台管理触发。
3. 业务逻辑热更：代码级上传，必要时集群同步。
4. 核心代码不热更。

## 3. CSV 配置热重载最小切片

当前已实现本地单进程 CSV 配置热重载最小切片：

- UTF-8 + 可选 BOM + RFC 4180，由 Apache Commons CSV 解析。
- 泛型 row decoder、显式 key、必需列、重复 key 和表级业务校验。
- 初始启动先构建并验证全部注册表候选，任一失败时零发布。
- 运行中使用不可变有序快照和 `AtomicReference` 完成单表原子替换。
- SHA-256 不变返回 `NO_CHANGE`；非法候选返回 `REJECTED` 并保留旧快照。
- 支持显式异步 reload 和默认关闭的本地 WatchService；文件 IO 与 watcher 使用 Starter 受管非内联 remote IO executor。
- 记录表名、脱敏来源、版本、摘要、行数、操作者、traceId、结果、耗时和 ErrorCode，不记录 CSV 行或完整路径。

Starter 必须显式配置 `zero.config.hot-reload.enabled=true`；watcher 通过 `zero.config.hot-reload.watch-enabled=true` 单独启用。完整 API、配置键、线程和风险边界见 [CSV 配置加载与本地原子热重载](guides/csv-config-hot-reload.zh-CN.md)。当前只承诺本地单表替换，不提供运行中多文件事务、Nacos/Kafka 集群同步、远程上传、签名审批或生产容量结论。

## 4. CGLIB 修复

CGLIB 代理用于线上 bug 与紧急业务修复。

适用范围：

- 经过框架代理的 service。
- 经过框架代理的 handler。
- 方法逻辑修复。

风险：

- 不适合安全修改已有对象内存结构。
- 字段结构变更风险高。
- 无法覆盖绕过代理的直接调用。

要求：

- 备份原始 class 到指定目录。
- 记录操作时间。
- 记录操作用户。
- 记录用户 IP。
- 记录权限。
- 记录目标类和目标方法。

## 5. ClassLoader 插件化

接口代理 + 独立 ClassLoader 插件化用于：

- 自定义脚本活动。
- 活动运营模块。
- 可卸载业务扩展。

要求：

- 插件必须实现标准活动接口。
- 插件必须声明版本。
- 插件必须声明依赖。
- 插件加载、启用、停用、卸载都必须记录审计日志。

## 6. 集群同步

热更需要支持集群同步。

同步内容：

- 热更类型。
- 版本。
- 目标模块。
- 校验信息。
- 操作人。
- 操作时间。
- 节点执行结果。

## 7. GM API 边界

GM API 仅能触发活动运营功能级热更，且需要权限审批。

更底层的修复性热更由框架管理能力负责，不作为普通 GM 功能开放。
