# 2026-10-08 审计 B3 迁移说明

本批完成 ownership、player、ranking 和 frame-sync 的 B3 复核与修复。项目仍处于 0.x；以下公共 API 和运行行为变更要求调用方在升级时同步处理。

## Player API 变更

- `PlayerLoginResult` 增加 `sessionId` record component。所有直接构造、解构或序列化该结果的调用方都必须更新。
- `PlayerService` 增加 `logout(PlayerLogoutRequest)`。网络连接关闭、踢线或会话替换完成后，接入层必须使用该次登录返回的 accountId、uid、sessionId 以及自己的 traceId 调用它。
- logout 只会删除精确匹配的当前会话。迟到的旧连接返回 `false`，不会删除新登录；同一 UID 的第二个账号登录会被 `UID_ALREADY_ONLINE` 拒绝。

示例：

```java
PlayerLoginResult login = playerService.login(request).toCompletableFuture().join();
playerService.logout(new PlayerLogoutRequest(
        login.accountId(), login.uid(), login.sessionId(), disconnectTraceId));
```

## Ownership 与 Ranking 行为

- `MigrationStore.transition` 不再接受小于当前 checkpoint 的版本；`FailoverCoordinator.recover` 拒绝 historyComplete 为 false 的 checkpoint。
- fenced state 只有通过当前 lease 校验后才会返回历史 requestId 的 receipt。内存实现默认最多保存 4096 条 receipt，满时拒绝新 requestId；生产调用方应将容量错误作为可观测的准入失败处理。
- 本地 ranking 对每个 board 最多保存 65,536 条 `(uid, idempotencyKey)` receipt。同键且 score、tieBreakValue、mode 相同才重放原结果；任一字段不同会拒绝。达到容量后必须切换赛季、使用持久化实现或按业务做显式容量规划。

## Frame Sync 行为

- `FrameMatchRuntime.tick(String traceId)` 可指定帧提交 trace；无参 `tick()` 使用 `frame-tick:<matchId>`。不再从第一条 input 取得 FrameCommitted 的 trace。
- 活跃参与者的旧或重复 inputSeq 直接忽略。`REPEAT_LAST` 的补输入使用当前 batch targetFrame。
- `maxParticipants` 同时限制尚未 leave 的 UID 水位数量；EMPTY/MARK 消费完输入也不会释放水位容量，迟到 MARK 输入同样受此预算约束。会话结束必须调用 leave，不能依赖输入消费回收会话名额。
- 传输和房间接入层必须在连接断开、离开房间或会话失效时调用 `leave(uid)`。该调用清理该 UID 的待处理输入、上一输入和序号水位；本批没有加入自动参与者超时。
