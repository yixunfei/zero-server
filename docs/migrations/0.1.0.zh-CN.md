# zeroServer 0.1.0 迁移说明

这是项目的首个 GitHub 源码预览版，不发布 Maven 制品，也不表示 `productionReady`。本次公开的 Maven 坐标版本为 `0.1.0`。从此前 `0.1.0-SNAPSHOT` 或未标记源码升级时，先按本文和各专项迁移说明调整应用。

## 破坏性变化

- Production network lifecycle 不再默认启用每 IP 限流、安全链、观测或心跳。应用需显式注入自己的 `NetworkRateLimiter`、`SecurityChain`、`ConnectionLifecycleObserver` 和 `ProductionNetworkPolicy`。省略限流器时不限制速率；省略安全链时由应用策略负责鉴权。握手/鉴权超时、入站预算与异常失败关闭仍由框架管理。详情见[生产网络生命周期迁移](20260928-production-network-minimal-customization.md)。
- `ProductionNetworkConfig` record 新增 `heartbeatEnabled` 参数；旧限流配置键及默认 IP 限流器已删除。若应用依赖这些配置或直接构造 record，按迁移文档更新。
- KCP 是独立可选 Adapter，不由核心网络或默认 Starter 自动引入。ZKCP/ZKCI v1、票据和保护策略与早期实现不兼容；旧客户端必须重新登录并消费 v1 连接描述。详情见[KCP 首轮接入](20260928-kcp-support.md)、[场景优化](20260928-kcp-scenario-optimization.md)和[高级传输迁移](20260928-kcp-advanced-transport.md)。
- KCP 不自动重放未确认请求；请求幂等、跨 TCP/KCP 顺序、断线后的会话恢复与客户端退避仍由应用协议决定。

## 验证证据

- Java 21、Maven 3.9.8：`mvn -B -ntp -Pquality clean install` 与 `mvn -B -ntp -Pquality verify` 的 60 个 Reactor 项目均成功；Surefire 共 960 项测试，0 失败、0 错误、0 跳过。
- `ZeroArchitectureGuard` 检查 59 个模块和 21 条规则，0 violation / warning；框架边界守卫与 `git diff --check` 通过。
- Redis 7.4 本地隔离环境中的 KCP Redis Lua 集成测试通过；KCP 独立示例的 5 类场景和 9 种保护/FEC 组合均完成本机验证。
- 上述结果不证明公网容量、Linux epoll、跨语言互操作、完整中间件故障矩阵或生产长稳。实际使用前应按部署环境单独验证。

## 已知限制

- 显式安装 observer 时，每连接的顺序投递队列没有容量上限。observer 回调应快速返回；慢回调或失控的自定义执行器可能造成队列积压。未安装 observer 的 no-op 路径不创建该队列。
- KCP `ALL` 示例曾在一次批量场景的登录取票阶段超时；单独运行和后续完整复验通过，根因未确认。这不是生产网络稳定性结论。
- 框架仍处于 0.x 预览阶段。容量、长稳、完整运营治理和正式制品签名/分发流程尚未形成发布门禁。

## 回滚

回滚框架与应用配置时，应同时回滚使用新公共 API 的应用代码。使用 KCP v1 的客户端必须与服务端保持同一协议版本；切回更早实现前，先停止新票据签发并让会话重新通过对应版本的登录/恢复流程。不要把不兼容的 KCP 票据或连接描述跨版本复用。
