# 数据安全、缓存与数据库兼容专项迁移说明

日期：2026-09-26
适用版本：`0.1.0-SNAPSHOT`
分支：`codex/quality-baseline-20260926`

本轮在提交 `9772f3e` 的线程、缓存和分布式一致性修复基础上，完成数据落库、缓存边界和数据库兼容审查。实现保持现有 Repository/DataService、缓存 SPI、envelope 编码、Redis key 格式和数据库 schema，不新增公共 API。

## 行为变化

- `RedisDriverEnvelopeStore` 的 namespace 和 collection 不得包含 `{` 或 `}`。这两个字符会改变 Redis Cluster hash tag 解析；已有不含花括号的 key 不受影响。
- `LocalDiskDataJournal` 的 namespace、collection 和 journal 路径片段拒绝控制字符、Windows ADS 冒号以及 `"*?<>|`。原有合法路径无需迁移。
- `AbstractRepositoryAdapter.registerRepository` 对重复名称抛出 `IllegalArgumentException`，首次成功注册的实例不会被替换。启动装配应保证名称唯一，并在失败时修正配置后重试。
- 内存仓库和 envelope 仓库分页在极大 `offset`、`limit` 下不再因整数溢出抛出非法范围异常；正常请求的项目、总数和游标语义不变。

## 迁移步骤

1. 检查 Redis envelope namespace/collection 配置，清理花括号；如果业务需要字面量花括号，请迁移到不含花括号的逻辑名称并允许缓存冷启动。
2. 检查本地 journal 配置，使用普通文件名片段，不要把用户输入直接作为路径片段。
3. 检查 Adapter 装配，确保每个 repository name 只注册一次；不要依赖后注册实例覆盖旧实例。
4. 重新运行数据模块定向测试和完整 Maven 门禁。

## 回滚

本轮没有数据格式或 schema 迁移。回滚代码前应先停止使用不符合新校验的名称，并确认没有依赖重复注册覆盖行为；数据库中的 envelope、Redis snapshot/cache key 和 journal 无需转换。

## 验证与边界

JDK 21 下 `zero-data`、`zero-cache`、`zero-data-redis` 定向测试共 102 个通过；Redis 7.4、MongoDB 7.0、PostgreSQL 16 单实例外部测试通过。完整 reactor 门禁结果和性能场景矩阵见[专项审查报告](../reports/data-cache-db-audit-20260926.zh-CN.md)。

本轮未证明 Redis Cluster slot 迁移、MongoDB replica set、PostgreSQL 高可用/连接池容量、跨数据库版本、进程强杀恢复、长稳、容量或 SLA。`findAll`/分页全量扫描、逐 key 批处理、同步 repository monitor 和默认非池化 PostgreSQL 连接仍是需要真实 workload 测量的容量风险。
