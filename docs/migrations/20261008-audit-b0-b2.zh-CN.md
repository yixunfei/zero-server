# 2026-10-08 审计 B0–B2 迁移说明

本批完成审计报告 B0–B2：B0 建账、去重和历史处置核对；B1/B2 修复已确认的 GM、审计、代理和安全上下文问题。B3–B7 未实施。

## 行为与 API 变化

- `SecurityContext` 从 record 改为不可变 final class，保留字段访问器；认证上下文增加本地单调到期预算。跨进程签名快照在收到时间验证，KCP 派生传输使用 `withTransport` 保留原预算。
- GM 响应新增 `businessCommitState`、`auditFailed`、`idempotencyFailed`。调用方不能仅凭 `code=ZERO-OK` 判断审计和幂等记账已完成。
- GM 指纹使用显式 HMAC 密钥；本地便利入口的随机密钥只适用于本地内存 store，持久化/多进程部署必须注入共享密钥。
- 在途幂等 claim 不按 TTL 回收；终态留存期从实际完成/失败记账时刻起算。进程崩溃恢复由应用持久化实现负责。
- 裸授权和执行旁路入口收为包内，外部调用统一经过 `GmOperationEndpoint`；DSL 统一受 4096 字符、64 token 上限约束。
- 空策略默认拒绝，HIGH/CRITICAL 自动要求审批，CRITICAL 或策略双人复核要求独立可信 verifier；验证服务异常返回授权拒绝。
- 审计 eventId/operationId 使用完整 UUID。`GmAuditRecordStore.containsExact` 默认 false，返回 DUPLICATE 的实现必须证明完整记录一致；REJECTED/null 不再被视为成功。
- 可信转发来源从右向左解析受信代理后缀；请求中伪造的最左地址不再被视为来源。权限元素统一校验，空权限头字段解析为空集合；诊断字符串固定脱敏。
- 失效查询游标返回 `AUDIT_CURSOR_INVALID`。查询是构造时快照，不随原列表变化；不自动从第一页重启。

## 升级步骤

1. 重新编译直接使用 `SecurityContext` 的模块；不得依赖 record 的自动 `equals/hashCode` 或组件模式。
2. 为持久化幂等实现配置跨实例一致的 HMAC 密钥和 key id。
3. REST 客户端读取新的提交状态和基础设施失败字段；`COMMITTED`、`UNKNOWN` 或记账失败不得盲目重试。
4. 接入可信第二复核人验证端口；未接线的 CRITICAL 或双人复核操作会拒绝。
5. 迁移旧四字段 `GmOperationResponse` 构造调用，明确传入提交状态与两个失败标记；为审计 UUID 字段预留至少 36 字符，并落实 DUPLICATE 精确查证。
6. GM 指纹和审计 ID 格式变化不兼容旧记录。开发环境重新初始化测试数据；需要保留真实记录时由应用显式设计迁移与密钥轮换，不能盲目删除已有业务数据。
