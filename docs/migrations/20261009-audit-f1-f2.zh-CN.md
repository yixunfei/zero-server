# 2026-10-09 审计遗漏 F1/F2 迁移

适用于 0.x 当前开发树；不改版本、不发布，无线格式或持久化格式变化。对应 [F1/F2 复核报告](../audits/2026-10-08-audit-final-recheck.zh-CN.md)。

## 玩家退出

调用方必须观察 `PlayerService.logout` 的异步结果。清理投递失败时，会话可能已经解绑；保留原 accountId、uid、sessionId，在服务与 scheduler 仍存活且容量恢复后重试相同请求，不必重新登录。traceId 不参与重试身份判定。不要在 Actor lane 内阻塞等待跨 lane 结果，也不要对持续背压无间隔重试。

- 待清理身份重试成功返回 true；清理已完成后重复请求返回 false。
- 同一清理在途请求共享物理尝试；取消返回 stage 的 CompletableFuture 观察者不取消内部工作。
- 同 UID 成功重新登录会永久撤销旧清理权限。原先已解绑的在途调用仍返回 true；此后的过期重试返回 false，旧清理不能删除新代际资料。
- 默认最多保留 4096 个待清理 UID。满额时新退出在解绑前以 `ZERO-PLAYER-CLEANUP-CAPACITY-EXCEEDED` 拒绝；处理既有待清理请求释放预算后再重试。
- 不新增后台自动重投。意图仅在内存中，服务关闭或 scheduler 永久停止后不能保证重试；应先完成业务退出清理再关闭资源。`close()` 不新增资料清空语义。

公共方法签名不变，新增 PlayerErrorCode 枚举常量；穷尽 switch 的调用方需处理容量错误。独立 `loadPlayer` 允许后续重新加载的契约未改变，本修复不保证退出后永远禁止资料加载。

## Java 生成器

在原先同包声明检查之外，现在按实际生成包检查所有包前缀，并在模板渲染前检查实际 import 的简单名称。validate/generate 使用同一输出计划预检，冲突在写文件、清单及 BO 实现前以 `DSL_VALIDATION_FAILED` 拒绝。

例如 `enum BoxDTOCodec` 被 `BoxDTOCodec` 引用、`enum codec` 与默认 `dto.codec` 包并存，不再输出不可编译产物。调整 DSL 类型名，或对包冲突调整 Java artifact package；仅移动输出目录不能解决 Java 名称冲突。自定义 DTO 后缀与分目录同样受检。

无引用的合法跨包同名类型及合法 `Class`/JDK 注解名称控制组保留支持。升级工具后运行 validate，再 generate、check，并编译实际产物；不要手改受管生成文件或清单摘要。

## 验证

修复前正式回归复现 3 个失败（F1 一个、F2 两个）；修复后的具体门禁、测试数量和限制见 [修复结果](../audits/2026-10-09-audit-f1-f2-results.zh-CN.md) 及其证据目录。历史无参 `readPresenceBits()` 删除导致的 API 基线问题不通过重写基线规避。
