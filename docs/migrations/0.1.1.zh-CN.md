# zeroServer 0.1.1 迁移说明

`0.1.1` 是 `0.1.0` 源码预览 tag 之后的 CI 与文档校正版本。本次不改变运行时 API、协议格式、配置、数据格式或依赖方向，不需要额外业务代码或数据迁移。首次从旧 `0.1.0-SNAPSHOT` 或更早实现升级时，仍须完成 [0.1.0 首发迁移](0.1.0.zh-CN.md)及相关专项说明。

## 使用版本

- Maven parent、BOM、框架模块和示例版本统一为 `0.1.1`。
- 本次只发布 GitHub 源码预览，不上传 Maven 仓库制品。消费者需从 `v0.1.1` tag 构建；不能假定 `0.1.1` 坐标已发布到公共仓库。
- `main` 在版本 tag 完成后转为 `0.1.2-SNAPSHOT`，供后续开发使用。

## 修复内容

- KCP TLS 登录示例测试等待票据的上限从 3 秒提高至 10 秒，避免慢速 CI 环境的误报；运行时超时和业务行为不变。
- KCP 示例改为在已认证登录帧的业务处理阶段签发票据，避免连接建立回调与认证完成顺序之间的竞态。
- Codegen 浏览器冒烟测试通过 `ProcessStartInfo.ArgumentList` 传递参数，兼容含空格的可执行文件和 profile 路径。
- 当前脚手架默认版本、示例及用户文档中的 release 坐标统一为 `0.1.1`。历史迁移记录、历史构建样本与明确标记的本地 SNAPSHOT 指引保持原样。

## 验证证据

- JDK 21 / Maven 3.9.8：`mvn -B -ntp -Pquality verify`，60 个 Reactor 项目通过；测试数和完整结果见本次任务 `VERIFY.md`。
- Java 21 架构守卫覆盖 59 个模块、21 条规则，0 violations / warnings；release readiness 通过 19 个路径和 32 个 marker 检查。
- `git diff --check` 通过；浏览器脚本语法通过。真实浏览器执行由 GitHub Codegen interop workflow 验证。
- 远端 `v0.1.0` 的 CI/interop 运行失败，因此发布 `v0.1.1` 前必须确认修复提交上的 CI 和 interop 全部成功。

## 已知边界与回滚

本版本仍是源码预览，`productionReady=false`，不提供生产容量或长稳承诺。没有运行真实浏览器的本机证据、外部中间件矩阵或公网压力结果。回滚到 `v0.1.0` 不需要数据回迁；如果已升级首次接入 API，则按 `0.1.0` 迁移说明一并回退应用代码和 KCP 客户端。
