# 0.1.0 P0-3 Adapter resilience 迁移说明

## 新增契约

`zero-runtime-production` 新增：

- `RuntimeAdapterHealth`
- `RuntimeAdapterRecovery`
- `RuntimeAdapterBudget`
- `RuntimeAdapterStateMachine`
- `RuntimeAdapterResilience`

这些类型通过显式 provider、budget 和调用方调度器组合，不创建隐式线程池或扫描 classpath。

## 兼容边界

- 现有 PAF1 startup budget/health 语义保持不变；P0-3 契约用于周期运行期，不能把 startup health 当作 recovery 证据。
- 未知写入结果默认不可重试；只有应用明确声明可重试且写入结果已知时，恢复策略才能返回 `RETRY`。
- `RuntimeAdapterBudget` 的 `maxRetry`、`maxInFlight`、operation timeout 和 backoff 必须显式配置并受边界校验。
- 当前契约不会自动改造 Kafka、Nacos、MongoDB、PostgreSQL 或 Redis driver 的连接恢复行为。
- 真实外部恢复仍需单独的 Compose/故障注入环境和数据一致性证据。

## 非目标

本切片不提供自动 rebalance、网络分区修复、连接池重建、分布式重试、幂等写入或生产容量/长稳证明；整体 `productionReady=false` 保持不变。
