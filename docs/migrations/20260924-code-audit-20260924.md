# 2026-09-24 代码审计修复迁移说明

本次修复针对 `docs/reports/code-audit-20260924.zh-CN.md` 中经源码控制流复核后成立的缺陷。项目仍处于 0.x，以下行为变化需要调用方在升级时检查。

## 行为变化

- GM 两参数 `GmOperationAuthorizer` 构造器现在对需要审批的操作默认拒绝；接入方必须显式提供 `GmApprovalVerifier`。仅检查上下文 `APPROVED` 状态的 `contextState()` 保留为显式选择。
- GM REST 请求的 `idempotencyKey` 进入 `GmOperationRequest`；重复的非 dry-run 请求会按端点幂等状态处理。`FAILED` 记录为终态，不会自动重试。
- 本次曾将 production runtime 的 data、cache、RPC 全局禁止 LOCAL provider；该策略连唯一的持久化管理器也禁止，导致完整 Starter 无法装配。2026-09-26 已按确认恢复既有的按需装配契约：未启用的 Adapter 可使用本地组件，显式启用后配置/创建/健康失败不得回退。当前行为和验证见[修复迁移说明](20260926-quality-baseline.md)。
- 场景重复进入会保留已有坐标；未进入场景的移动请求失败。稳定 hash UID 改为 SHA-256 截取的非负值，仍不提供数学意义上的全局无碰撞保证。
- UDP datagram 超过 `ServerOptions.maxFrameLength` 会被拒绝；同一发送端使用稳定连接标识。HTTP 同名请求头统一拒绝，避免后者覆盖前者。
- 已认证 TCP 连接上的单帧 replay 检查失败只拒绝该帧并继续连接；生命周期 observer 可通过 `FRAME_REJECTED` 观察该事件。

## 数据与并发

- Redis 条件写 Lua 只操作同 bucket hash tag 的 key；集合索引在脚本成功后单独维护，Redis 执行失败不会把未提交对象写入本地 journal。
- world 状态表的 lane 操作和查询由共享状态锁串行化；事件 sink 异常向调用方传播。房间事件消费者失败时本地房间状态回滚，断线重连时间必须位于 `[disconnectedAt, disconnectedAt + window]`。
- Layered cache 先完成 L2 失效，再删除 L1，消除旧值回填窗口。同步 RPC 超时会取消本地 transport stage；服务端仍必须依据请求 deadline 自行决定是否提交。

## 尚未改变的边界

- 真实 Redis Cluster、TLS、Kafka 服务端提交和 UDP production lifecycle 仍需要外部集成环境验证。
- HTTP 独立在途预算、协议字段独立上限、启动异常脱敏 cause 需要单独的 API/诊断设计，本次未作猜测性改动。
