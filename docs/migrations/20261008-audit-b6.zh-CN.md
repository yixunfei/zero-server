# 2026-10-08 审计 B6：代码生成与工程验收

本次适用于 0.1.2-SNAPSHOT 开发工作树，不发布新版本。服务端协议 ID、线格式、SPI、线程和业务存储契约不在本批变更范围。验证结果以本页末尾及本机 B6 台账为准。

## 工具行为与调用方迁移

- `validate` 现在完成 DSL、全部目标模板和只读输出归属预检。合法空输出目录返回 0 且不创建目录；已手改受管生成物或 pending 事务返回 1。`check` 发现待生成、更新或过期文件返回 3；参数错误返回 2。
- BOImp 仍是只创建一次的业务模板，已有文件为 `preserve`，业务修改不算生成漂移。受管 DTO/codec 等须先人工合并或恢复，不能靠添加生成标记绕过已有摘要。
- `GeneratedOutputPlan()` 无参构造删除；调用方改为 `new GeneratedOutputPlan(root, allowedRoots)`。四种公开 `render(request)` 均完整渲染、预检并使用受管事务；多语言聚合入口共享同一计划。单文件 writer 不提供跨文件事务。
- 标识符采用可移植 ASCII 名称，实际目标语言关键字、生成器保留符号、派生类型冲突和大小写文件名冲突提前失败；不自动转义或改名。Java 包与分类目录可继续显式配置。类型最大深度 64，根节点、泛型参数、nullable/optional 和每层数组均计入；程序化模型同样受限。
- 输出路径拒绝设备名（含扩展名）、控制/非法字符及尾点、尾空格；继续拒绝符号链接和路径越界。feature 字面量按枚举声明顺序输出；生成源码与脚手架统一 LF，自定义 CRLF 模板也先规范行尾再计算 ownership 摘要。

## 输出恢复日志 schema 2

`.zero-codegen/pending.json` 新增 `PREPARED` / `COMMITTED` 阶段。所有后像写入后先保存提交事实，再清理日志：

| 状态 | `recover` | 下次 generate/prune |
| --- | --- | --- |
| PREPARED | 校验前后像后回滚 | 拒绝，要求显式 recover |
| COMMITTED | 校验后像后只清理，不回滚产物 | 持锁清理后重新预检 |
| schema 1 | 拒绝并提示先用原工具恢复 | 拒绝 |
| 外部内容不符 | 保留文件与日志，失败 | 失败 |

提交后清理/释放资源失败以 `OUTPUT_COMMITTED_CLEANUP_FAILED` 表示，不能据此判定业务内容没有写入。升级前如有 schema 1 pending，先在原配置下用原版本 `--mode recover` 处理，并检查所需产物；旧 recover 会恢复 before。不要手工改 schema 或删除 pending 来强行生成。降级前也须用当前版本完成 schema 2 恢复，并保存工作树与工程副本。

锁只约束协作工具。最后一次内容检查与文件替换之间没有跨平台 CAS 保证；生成/恢复期间应停止编辑和构建。多文件写入不对读者同时可见，不承诺断电耐久性。

## 脚手架首次创建

首次生成先在独立 staging 完整渲染，再全量预检、持工程升级锁提交。正常写入失败仅撤销本次新建且内容匹配的文件；空目录和锁文件可能保留，可直接重试。`--force` 仅允许非空目录，已有相同内容保留，已有不同内容拒绝；未知文件不覆盖。

首建恢复指针是 `.zero/scaffold/create.json`，与协议工具 journal 独立。使用 `java scripts/NewLocalGame.java --outputDir <工程> --rollback`：PREPARED 撤销本次新建文件，COMMITTED 仅校验并清理。外部编辑阻断恢复时保留材料，先人工处理；升级 plan/apply 拒绝未处理的首建日志。不要删除工程锁文件。

模板 token 仅扫描原模板一次，替换值不会再次被解释；未知 token 拒绝。版本号仅允许以字母或数字开头的字母、数字、点、下划线和连字符，禁止 `__`。旧 CRLF 产物升级可能出现真实差异，先 plan 审查，不覆盖手改。

## 验收脚本

BAT、性能脚本、interop 与 NewLocalGame 解析根 POM 精确版本，不按文件时间挑选旧 jar。先使用当前源码运行 Maven wrapper 构建；同版本 jar 的存在本身不证明源码新鲜。BAT 接受显式 CLI 参数并透传退出码。no-SDK 与 Adapter 门禁先安装当前依赖。

Adapter 门禁校验本次 UUID 对应的目标类 XML，要求至少一个实际执行测试、失败和错误均为 0；依赖 reactor 无匹配测试可跳过，目标类缺失、全跳过、陈旧报告都失败。CI 增加 `VerifyCodegenModes`，显式 bash 的 pipefail 和 Windows 原生命令检查防止前序错误被成功命令掩盖。不会改变外部中间件或性能 opt-in 条件。
