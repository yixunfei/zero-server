# C1-C8 可靠性修复迁移说明

## 适用范围

本说明对应 2026 年 10 月 2 日的 C1-C8 审查修复，适用于 0.x 开发阶段接入。

## 行为变化

- Kafka RPC oneway handler 抛出异常后，消费端会记录失败并确认该消息，避免同一 offset 无限重投。请求 envelope 解码失败也会被隔离并确认；业务侧如需补偿，应在 handler 或外部审计中自行记录。
- Kafka reply topic 使用网关实例独占的 consumer group。多节点可以继续共享 reply topic，不应再手工把 reply consumer group 配成所有节点相同的固定值。
- Redis driver journal 每个对象只保留最近 1024 条记录。需要完整历史的场景应使用 `LocalDiskDataJournal` 或外部审计存储。
- 事件拦截器返回 `false` 会使 `publish` 阶段失败，并写入死信；调用方不能再把返回成功当作“事件被拦截后已成功发布”。
- `ProjectScaffoldGenerator` 的 `--force` 只允许对内容未变化的目标文件幂等重跑。已被用户修改的文件会抛出冲突并保持原内容。
- scaffold upgrade 会把新模板文件标记为 `generator-added` 并纳入 apply；应用后下一次 plan 应为空。
- LocalWorldService 的 `events()` 返回最近 4096 条提交事件，旧事件会淘汰。
- PostgreSQL ownership `assertCurrent` 在同一事务中完成 lease 行锁和数据库时钟读取，连接关闭时事务自然结束。

## 验证边界

Kafka、Redis、PostgreSQL 的真实外部 broker/服务行为仍需在对应 external profile 下验证；本次默认单元测试覆盖的是消息处理、事务边界、脚手架比较逻辑和事件历史容量。
